# セキュリティ

この文書は認証、トークン、ネットワーク露出、エラー情報の扱いを説明します。OAuth のプロトコル挙動は [OAuth の仕組み](oauth.md)、運用時の復旧は [運用](operations.md) を参照してください。

## 認証モード

`auth.mode` は必ず明示します。

- `oauth`: OAuth 2.1 と静的 Bearer トークンを併用します。外部クライアントに接続する場合の推奨モードです。
- `none`: 認証なし。URL に到達できる利用者が OCR データを検索できるため、ローカルの動作確認などに限定します。インターネットへ公開しないでください。

認証用 DB が使えない場合、サーバーは認証なしへ切り替えません。`auth.mode` が明示的に `none` でない場合や認証ゲートを構築できない場合は `/mcp` を fail-closed にして 503 を返します。

## トークンの管理

- `npm run token -- create --name <名前> --purpose login|api` で目的別のトークンを発行します。
- トークン本体は発行時に一度だけ表示されます。安全なパスワードマネージャーなどに保存してください。
- 名前は端末・用途ごとに分けると、漏えい時に該当トークンだけを失効できます。
- API トークンには `--expires-in-days 90` のように有効期限を設定できます。API トークンは、失効または期限切れになるまで使用できます。
- トークン接頭辞は `ocrmcp_api_` または `ocrmcp_login_` です。接頭辞は秘密情報保護の代わりにはなりません。
- トークン本体や認可コードの生値は DB に保存せず、SHA-256 ハッシュを保存します。認証 DB はファイル `0600`、ディレクトリ `0700` の権限で作成する設計です。
- トークンを URL のクエリ文字列、ソースコード、リポジトリ、共有可能な設定ファイル、プロンプトやチャット本文に含めないでください。Bearer トークンは `Authorization` ヘッダーで渡します。

主な操作：

```bash
npm run token -- list
npm run token -- revoke --name claude-code
npm run token -- create --name claude-code --purpose api --expires-in-days 90
```

`list` でトークン本体は表示されません。詳しい接続例は [クライアント接続](clients.md) を参照してください。

## スコープと書き込み

`ocr:read` は常に付与されます。書き込みツールは `ocrWrite.enabled: true` のときだけ登録され、この設定には `auth.mode: "oauth"` が必須です。`update_ocr_text` は `authInfo.scopes` に `ocr:write` が含まれる場合だけ実行します。`reviewed IS NOT 0` の行は変更を拒否します。

## ネットワークと Host 検証

- Node.js は例として `127.0.0.1:3001` で待ち受け、外部アクセスは Caddy 等の HTTPS reverse proxy を通します。ポート 3001 を直接ルーターから公開しないでください。
- `server.publicBaseUrl` は HTTPS の origin として設定し、`server.allowedHosts` の許可対象を意図せず広げないでください。
- OAuth の `redirect_uri` は許可リストと一致するだけでなく、HTTPS またはループバック HTTP であることを検証します。
- CIMD のメタデータ取得先ホストは `oauth.cimdAllowedHosts` に制限され、HTTP リダイレクトには追従しません。
- Caddy 等のプロキシで OAuth の Content-Security-Policy を不用意に上書きしないでください。

## エラーとログ

MCP クライアントに返すエラーには、ローカルファイルパスや SQLite / `fs` ドライバの詳細を含めません。許可された `ClientSafeError` の文言や入力エラーを除き、予期しない例外は汎用メッセージに置き換え、原因をサーバーログに記録します。

起動ログには失敗した設定キーやパス、障害の詳細が含まれることがあります。ログファイルとログ閲覧権限も秘密情報と同様に管理してください。ログを外部に共有する場合は、パス、ホスト、クライアント情報などを確認してから共有します。

## DB・ファイルシステムの境界

- 通常の OCR Repository は読み取り専用接続を使います。書き込みを明示的に有効化した場合だけ別の書き込み接続を開きます。
- OCR 書き込みは本文20,000 UTF-16コード単位かつUTF-8で64 KiB以下、HTTPリクエスト本文は1 MiB以下です。クライアント単位は直近60秒あたり10回、サーバー全体は30回までです。
- 元画像ツールは対応する画像形式だけを返し、画像1ファイルの取得上限は 20 MiB です。読み込みと Base64 化は1つの Worker で直列化し、FIFO の待機上限は30件です。
- 元画像ツールはディレクトリ名・ファイル名を受け取り、絶対パスや親ディレクトリへの移動を許可しません。シンボリックリンクやパストラバーサルへの防御も行います。
- 認証 DB は OCR DB とは別ファイルにし、権限を分離します。
- MCP 編集履歴には旧本文・新本文の UTF-8 バイト数も記録します。既存履歴のバイト数は列追加時に一度だけバックフィルし、通常起動時は本文そのものを読み直さず、バイト数列を集計して警告値を求めます。履歴件数は削除しない運用を前提に最大 ID で概算します。

## OAuth 実装について

このサーバーは必要なフローを実装した独自の OAuth 実装です。ビルドとテストが通ることだけで、すべてのクライアントとの互換性が保証されるわけではありません。実際の利用クライアントで discovery、認可、トークン発行、refresh まで確認してください。
